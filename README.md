```bash

실행 후 아래 메뉴가 표시되며, 번호를 입력해 모드를 선택합니다:

```

- **모드 1 (`1` 입력)**: 3×3 필터 A, 필터 B, 패턴을 직접 콘솔에 한 줄씩(공백 구분) 입력합니다.
- **모드 2 (`2` 입력)**: 프로그램과 **같은 디렉토리에 있는 `data.json`** 을 자동으로 로드하여 일괄 분석을 실행합니다.

### 모드 1 — 사용자 직접 입력 흐름

```
필터 A (3줄 입력, 공백 구분)
> 0 1 0
> 1 1 1
> 0 1 0

필터 B (3줄 입력, 공백 구분)
> 1 0 1
> 0 1 0
> 1 0 1

패턴 (3줄 입력, 공백 구분)
> 0 1 0
> 1 1 1
> 0 1 0
```

입력 오류(개수 불일치, 숫자 아닌 값)가 발생하면 안내 문구와 함께 재입력을 유도합니다.

### data.json 구조

```json
{
  "filters": {
    "size_5":  { "cross": [[...]], "x": [[...]] },
    "size_13": { "cross": [[...]], "x": [[...]] },
    "size_25": { "cross": [[...]], "x": [[...]] }
  },
  "patterns": {
    "size_5_1":  { "input": [[...]], "expected": "x" },
    "size_5_2":  { "input": [[...]], "expected": "+" }
  }
}
```

- `filters` 키: `size_{N}` (N = 5, 13, 25)
- 각 필터 내부 키: `"cross"` 또는 `"x"` (라벨 정규화로 `Cross`/`X`로 표준화됨)
- `patterns` 키: `size_{N}_{idx}` 형식. 키에서 N을 추출해 해당 크기의 필터를 자동 선택
- `expected` 값: `"+"` (Cross) 또는 `"x"` (X)

## 구현 요약

### 라벨 정규화 방식

`data.json`의 필터 키(`"cross"`, `"x"`)와 `expected` 값(`"+"`, `"x"`)을 모두 프로그램 내부 **표준 라벨**인 `Cross` / `X`로 통일 변환합니다.

| 입력 값         | 표준 라벨 |
|----------------|-----------|
| `"+"`          | `Cross`   |
| `"cross"`      | `Cross`   |
| `"x"` (소문자) | `X`       |

이를 통해 기호·대소문자 차이에 의한 오판정 오류를 방지합니다.

```python
LABEL_MAP = {'+': 'Cross', 'cross': 'Cross', 'x': 'X'}

def normalize_label(value):
    return LABEL_MAP.get(value.lower().strip(), value)
```

### MAC 연산 구현 개요

외부 라이브러리(NumPy 등) 없이 **이중 반복문**으로 직접 구현합니다.  
입력 패턴과 필터의 같은 위치 원소를 곱한 뒤 누적 합산하여 유사도 점수(float)를 반환합니다.

```python
def mac_operation(pattern, filter_matrix):
    n = len(pattern)
    total = 0.0
    for i in range(n):
        for j in range(n):
            total += pattern[i][j] * filter_matrix[i][j]
    return total
```

- 지원 크기: 3×3, 5×5, 13×13, 25×25 (n×n 모두 처리 가능)
- 점수가 높을수록 입력 패턴이 해당 필터와 유사함을 의미

### 동점 처리 정책 (epsilon)

부동소수점 연산의 이진수 표현 한계로 발생하는 미세 오차를 처리하기 위해 **허용오차(epsilon)** 기반 비교 정책을 적용합니다.

```python
EPSILON = 1e-9

def compare_scores(score_cross, score_x, epsilon=EPSILON):
    if abs(score_cross - score_x) < epsilon:
        return 'UNDECIDED'   # 동점 → 판정 불가
    return 'Cross' if score_cross > score_x else 'X'
```

- `|Cross 점수 - X 점수| < 1e-9` → `UNDECIDED` (판정 불가)
- `UNDECIDED`인 경우 PASS/FAIL 비교 시 `FAIL (동점 규칙)`으로 처리

## 결과 리포트

### FAIL 케이스 원인 분석

총 **8개** 케이스 중 **6개 PASS, 2개 FAIL**이 발생했습니다.  
FAIL 원인은 명세(E1-3 §3)에 따라 세 카테고리로 분리 진단합니다.

#### 1. `size_13_3` — **[수치 비교 문제]** FAIL

- **현상**: 입력 패턴이 모든 셀이 `1`로 채워진 13×13 행렬입니다.
- **MAC 결과**: Cross 필터 점수 = `25.0`, X 필터 점수 = `25.0` (완전 동점)
- **판정**: `|25.0 - 25.0| = 0 < 1e-9` 이므로 epsilon 정책에 의해 `UNDECIDED`
- **원인**: 입력 데이터 자체가 두 필터 모두에 균등하게 반응하는 구조이므로 로직 결함이 아니라 **수치 비교 상황**에서 동점으로 판정 불가 처리된 것
- **결론**: epsilon 기반 동점 처리 규칙이 정상 작동한 결과이며, `expected: X`와 다르므로 `FAIL`

#### 2. `size_5_3` — **[데이터/스키마 문제]** FAIL

- **현상**: 패턴 키는 `size_5_3`(5×5 기대)이나, `input` 배열이 3×3 크기
- **감지 방법**: MAC 연산 수행 전 `validate_matrix(pattern, 5)` 검증 실행
- **결과**: 행 수 불일치(3 != 5) 감지 → 프로그램 중단 없이 해당 케이스만 `FAIL` 처리
- **원인**: 데이터 오류(잘못된 입력 크기)이며 로직이나 알고리즘 문제가 아님
- **결론**: 스키마 검증 로직이 정상 작동했으며, 프로그램 비정상 종료 없이 케이스 단위 FAIL 처리 요구사항을 충족

#### 3. [로직 문제] 발생 없음

- 정상적인 5×5, 13×13, 25×25 Cross/X 패턴 6개는 모두 예상대로 `PASS`
- 알고리즘 자체의 연산 오류나 잘못된 판정은 없었음

### 성능 분석 표 및 시간 복잡도 해석

각 크기별 MAC 연산을 **10회 반복 측정**하여 I/O를 제외한 순수 연산 시간의 평균을 측정했습니다.

| 크기 (N×N) | 연산 횟수 (N²) | 평균 시간 (ms) |
|-----------|--------------|--------------|
| 3×3       | 9            | 0.001        |
| 5×5       | 25           | 0.002        |
| 13×13     | 169          | 0.011        |
| 25×25     | 625          | 0.039        |

#### O(N²) 시간 복잡도 근거

MAC 연산의 핵심 로직은 **이중 반복문** 구조입니다:

```python
for i in range(n):      # N번 반복
    for j in range(n):  # N번 반복
        total += pattern[i][j] * filter_matrix[i][j]
```

- 총 곱셈 연산 횟수 = **N × N = N²**
- N이 5 → 25로 5배 증가할 때, 연산 횟수는 25 → 625로 **25배(= 5²) 증가**
- 실측 시간도 0.002ms → 0.039ms로 약 **19.5배 증가** (이론적 25배에 근접)

이 관계가 O(N²) 시간 복잡도를 실증합니다.  
실제 AI 모델은 수백×수백 필터를 수천 개씩 사용하므로, N이 커질수록 연산량이 폭발적으로 증가해 NPU 같은 전용 병렬 처리 장치가 필수적입니다.
