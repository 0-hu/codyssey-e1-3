# Mini NPU 시뮬레이터

## 1. 실행 방법
- **프로그램 실행**: 콘솔(터미널)에서 `python main.py` 명령어로 실행합니다.
- **모드 선택**: 실행 후 나타나는 메뉴에서 번호를 입력하여 모드를 선택합니다.
  - `1`: 사용자 입력 (3×3 필터 직접 입력)
  - `2`: `data.json` 자동 분석
- **테스트 데이터 (`data.json`)**: 프로그램과 동일한 디렉토리에 위치해야 하며, 사전에 지정된 형식으로 필터와 패턴 목록 정보를 구비해야 합니다.

## 2. 과제 목표 달성 및 핵심 개념 설명 (구현 요약)

이번 시뮬레이터에서 구현한 핵심 원리와 이유에 대해 기술합니다.

### 가. MAC 연산과 유사도 계산의 원리
- **MAC 연산이란?**  
  입력 데이터 행렬과 특징을 추출하는 필터 행렬을 서로 포개어 겹치는(같은) 위치의 값끼리 곱(Multiply)하고, 그 결과를 모두 하나로 더하는(Accumulate) 연산입니다. 
- **유사도 판정 원리**:  
  이 MAC 연산을 거쳐서 산출된 결괏값(점수)이 클수록 입력된 패턴이 현재의 필터와 "형태/모양이 유사하다"는 의미를 갖습니다.
- **AI에서 MAC 연산이 중요한 이유**:  
  AI, 특히 딥러닝 기반 이미지 처리(합성곱 신경망 등) 영역에서는 이미지를 처리하기 위해 수십수백 개의 필터로 픽셀 연산을 처리합니다. 이미지 한 장 처리에만 수억 번의 MAC 연산이 발생하며, CPU 같은 직렬 처리 장치 대신에 수천 개의 MAC 연산을 동시에 병렬 연산할 수 있는 전용 칩셋(NPU)을 설계하여 사용하는 것이 최근 AI 시스템의 핵심입니다.

### 나. 라벨 정규화(표준화) 정책 적용
- **왜 라벨 정규화가 필요한가?**  
  `data.json` 포맷뿐만 아니라 다양한 소스의 데이터는 데이터를 식별하는 값이나 키보드 입력 차이때문에 기호(`+`, `x`), 영문 표기(`cross`, `Cross`, `X`) 등이 혼용될 수 있습니다. 
- **해결 및 적용**:  
  프로그램 내부에서 이런 값을 그대로 비교하면 같은 의미인데도 다르다고 판단하는 `False Negative` 치명적인 논리 결함이 발생할 수 있습니다. 이를 막기 위해 `normalize_label()` 함수를 구현해 모든 라벨을 `Cross` 및 `X` 라는 내부 통일 규격으로 정규화하여 사용했습니다.

### 다. 부동소수점 오차 처리 정책 (epsilon)
- 컴퓨터의 실수 연산은 이진수 표현의 한계로 인해 `0.9` 와 같은 딱 떨어지는 소수를 표현할 때 미세한 오차가 발생합니다 (예: `0.89999999999999...`). 
- 이 때문에 수학적으로 동일하게 나와야 하는 결과도 `=` 연산자를 쓰면 서로 다르다고 평가되어 오판정 오류가 날 수 있습니다.
- 이를 예방하고자 두 점수의 차이 절대값이 `1e-9` (epsilon) 이내라면 이를 "동점"으로 인정하는 허용오차 정책을 부여했습니다. 본 프로그램에서 동점이 나올 경우 `UNDECIDED`를 출력합니다.

## 3. 결과 리포트

### 실패 원인 카테고리 진단 분석
과제 평가를 위해 의도적으로 만든 `data.json` 분석 결과, 총 8개 케이스 중 의도한 부분에서 2건의 `FAIL`이 발생하였으며 문제를 3가지 진단 카테고리(데이터/스키마, 수치 비교, 로직)로 분리 분석했습니다.

1. **`size_13_3` 케이스: [수치 비교 문제]로 인한 FAIL**  
   - **현상**: 입력 패턴이 모두 `1`로 채워져 있어 `Cross` 필터와 `X` 필터 모두 동일한 MAC 점수(25.0)가 나왔습니다.
   - **진단 및 처리**: 로직은 정상이나 두 값이 완전히 같은 수치 비교 상황입니다. 따라서 동점 처리 정책(epsilon)에 따라 `UNDECIDED` 처리되었으며, 예측치(`expected`)인 `X` 값과 다르므로 `FAIL (동점 규칙)`으로 결론내렸습니다.

2. **`size_5_3` 케이스: [데이터/스키마 문제]로 인한 FAIL**  
   - **현상**: 키 명세와 필터는 `size_5`(5×5) 구조이나, 주어진 테스트의 Input 배열은 3×3의 크기를 가졌습니다.
   - **진단 및 처리**: MAC 연산 수행 전에 미리 `validate_matrix()` 검사를 구동 시켜 `크기 불일치(행 수 불일치: 3 != 5)`를 감별해냈습니다. 이로 인해 프로그램 비정상 종료를 예방하고 [데이터/스키마 문제]로 진단해 해당 개별 케이스만 우아하게 `FAIL` 처리했습니다. 

*(본 시뮬레이터에서는 알고리즘에 이상이 있는 [로직 문제] 결함은 발견되지 않았습니다.)*

### 시간 복잡도(O(N²)) 분석
성능 측정 기능으로 각 크기별 필터에 대해 순수 MAC 연산 시간을 10회씩 측정한 평균입니다.

| 크기 (N×N) | 곱셈 연산 횟수(N²) | 평균 경과 시간 |
|-----------|------------------|----------------|
| **3×3**   | 9회              | 0.001 ms       |
| **5×5**   | 25회             | 0.002 ms       |
| **13×13** | 169회            | 0.011 ms       |
| **25×25** | 625회            | 0.038 ms       |

- **분석 근거**: 
  N이 5에서 25로 **5배 증가할 때**, 총 연산 횟수는 25번에서 625번으로 N의 제곱수 비율인 **25배 증가**했습니다. 그리고 실제 측정된 경과 시간 벤치마킹 데이터 역시 0.002ms에서 0.038ms로 근접한 상승 배율(약 19배) 양상을 보입니다.
- **결론 도출**: 
  MAC 연산을 구현한 핵심 로직은 전체 행렬 공간을 탐색해야 작동하므로 명백한 이중 반복문 구조(`for i in range(n) -> for j in range(n)`)를 갖습니다. 따라서 입력 길이 `n` 증가에 따라 연산 횟수가 O(N²)으로 기하급수적으로 증가하며, 이 사실을 위 성능 표 측정을 통해 실증할 수 있습니다.
